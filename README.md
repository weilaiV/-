# 科然数智 · 企业经营工作台

面向公司内部 10～30 人的经营管理系统首版。界面参考经营驾驶舱，独立实现业务逻辑与数据库。原站账号、密码和业务数据未纳入项目。

## 当前功能

- 首次创建管理员、登录/退出、七天会话。
- 管理员与只读成员两种角色，服务端强制权限。
- 销售、退款、毛利、预估净利、成本与费用指标。
- 日期及渠道筛选、等长周期环比、销售趋势、渠道/店铺/商品排名。
- 店铺与商品明细搜索，每页 20 条。
- UTF-8 CSV 模板、预检、整批导入、重复检查、最近 100 批历史。
- 独立标记的合成演示数据，不能混入真实数据。
- 团队账号创建、Docker 部署配置、GitHub Actions 检查。
- 原站11模块目录、页签切换与关闭、Ctrl/Cmd+K页面搜索，待还原入口明确禁用。
- 老板工作台指标贡献抽屉、店铺/平台/商品下钻、经营变化提醒及依据、按账号保存展示板块。
- 经营财务已启用公司经营总览、核算中心、费用管理：12项月费录入/修改/归档恢复与列设置；安全公式及依赖预览；跨月费用按自然日分摊并显示缺月提醒。

整站分模块进度与 REA 使用范围见 [还原计划](docs/superpowers/plans/2026-10-22-reference-rebuild.md)，财务本批验收见 [费用与核算记录](docs/verification-finance-2026-10-22.md)。目录候选数量不代表已完成页面数；财务11入口目前启用3个，其他模块继续开发。

这是第一阶段，不是原站全部业务模块的完整复刻。财务对账、客户、供应链、人效、AI 等模块需按实际业务继续开发。当前仅支持 CSV；Excel 请另存为 CSV UTF-8。

## 本地启动

要求 Node.js 24（项目使用内置 `node:sqlite`；该版本会打印 SQLite 实验特性提示）与 npm。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 ，第一次由你自行设置管理员账号及至少 12 位密码。没有预置的正式账号，也不使用参考网站密码。默认数据存于 `data/keran.sqlite`，数据库、日志、环境文件均被 Git 忽略。

也可以运行构建后的单服务版本：

```sh
npm run build
npm start
```

打开 http://127.0.0.1:3001 。开发与构建版本使用相同的本地数据库，不要同时启动两个占用 3001 端口的服务。

停止时在启动网站的终端按 Ctrl+C；只关闭浏览器页面不会停止服务。项目不设置开机自启或常驻服务。

更新代码后，运行 `npm run build`，再停止并重新运行 `npm start`，让后端加载新功能。数据库会增量建表，原账号、经营记录保留。当前代码未预置或复制原站的费用/规则数据，需由管理员维护。

管理员可点击「先体验演示数据」，生成 90 天合成记录。导入真实数据前须明确清除演示数据。清除仅针对合成记录，不删除账号或真实经营记录。

### 一次性预览

```sh
npm run build
node tests/preview.mjs
```

打开 http://127.0.0.1:3002 ，仅此内存预览环境使用账号 `preview`、密码 `Preview-only-2026`。停止预览进程后数据全部消失，预览脚本只监听本机。正式环境不会创建该账号。

## CSV 与财务口径

在「数据导入」下载模板。完整列名如下，可调整列顺序：

```csv
日期,渠道,店铺,商品,销售额,退款额,产品成本,广告费,平台费,运费,仅退款,退货退款,奖励
2026-10-21,天猫,示例店铺,示例商品,1000.00,50.00,500.00,30.00,10.00,15.00,30.00,20.00,5.00
```

- 一行表示一个日期、渠道、店铺和商品的汇总；该四项组合必须唯一。数据库中已有相同组合时拒绝整批，不静默覆盖。
- 日期范围 2000-01-01～2100-12-31。每次查询最多 366 天。工作日历采用 Asia/Shanghai。
- 所有金额单位为人民币元，非负、最多两位小数，每项单行不超过一千万元；服务端以整数分保存和累加。
- 原10列表头继续兼容。仅退款、退货退款、奖励为可选列；两类退款必须成对提供，且合计等于退款额。缺失列显示为未提供，不推算拆分金额；奖励缺失时暂按0计入预估净利润，需补齐后用于正式核算。
- 退款额不超过该行销售额。本版不处理销售为零但发生历史退款的跨期退款明细，需先按业务汇总口径整理。
- 净销售额 = 销售额 − 退款额；毛利额 = 净销售额 − 产品成本。
- 预估净利 = 毛利额 + 已提供奖励 − 广告费 − 平台费 − 运费。尚未计入未导入的税费、人工、租金等费用，不能直接视为会计净利润。
- 毛利率与净利率以净销售额为分母；分母为零返回零。环比比较等长上一周期，无前期基数显示暂无对比。
- 文件最大 5MB，最多 10,000 行；无效日期、金额、重复行、公式前缀、缺失表头均拒绝整批。
- 本版适合统一整理后的经营汇总数据，不直接解释淘宝、京东等各平台的原始账单；后续需分别开发字段映射。

## 库存经营

从「供应链 → 库存经营」进入，或打开 http://127.0.0.1:3001/#inventory 。库存与经营汇总、公司费用分开保存。

- 管理员上传同格式 ERP `.xlsx` 商品资料表（最大 4MB），先预检，再确认保存；读取第一张工作表。公式须先转为数值。
- 每次导入为完整快照，默认显示最近导入批次，可以切换历史快照；多个批次库存不累加，同一文件拒绝重复导入。
- 建议每天固定时间导出并导入一次，批次日期选择导出当天。前一天的数据继续保留；同一天的不同文件也会保留为独立快照。目前支持历史切换，尚未提供跨日趋势图；库存减少不能直接当作销量。
- 支持商品编码、名称、规格、款式、标签及状态筛选，排序、分页和完整原表字段详情；编码按文本保留前导零。
- 安全库存预警只使用正数上下限；空白销量显示「未提供」，与真实零销量区分。滞销、清货、下架标签来自原表。
- 批次日期、导入时间和原表商品更新时间分别保留。列表按可见行懒加载商品缩略图，可点击打开原图；缺图和加载失败分别显示占位。仅加载支持的ERP公网HTTPS图片来源，不发送页面Referrer，服务器不代理图片；其他来源可在详情主动打开。
- 原表未提供成本单价与仓库维度，因此不计算库存金额和仓库分布。预警供核对原表，不会自动采购或修改库存。

已有管理员的本机数据库也可通过命令导入。命令先解析并预检，再使用 SQLite 一致性备份，最后事务写入库存表：

```sh
npm run inventory:import -- "/absolute/path/inventory.xlsx" 2026-10-24
```

数据、备份及真实文件均保留在本机，不提交公开 GitHub。库存验收见 `docs/inventory-verification-2026-10-24.md`。

## GitHub 管理

远端由用户指定为 https://github.com/weilaiV/- 。提交前检查 `git status`，只提交源码、模板、测试和部署配置。该仓库初始为公开仓库；数据库、密码、密钥、业务 CSV 均不得提交。企业若需要限制源码访问，可由仓库所有者改为私有。

每次推送和 PR 会触发 GitHub Actions：安装锁定依赖 → 测试 → 语法检查 → 生产构建。现阶段不配置自动上线。

## 以后部署

建议起步 4 vCPU / 8GB RAM / 100GB SSD，国内员工可选择大陆节点并按要求办理域名备案。本阶段未购买或部署云服务器。

1. 在服务器创建 `.env`：

```dotenv
PUBLIC_ORIGIN=https://your-domain.example
SETUP_TOKEN=replace-with-a-random-secret-at-least-32-characters
```

生成随机令牌（请只在服务器终端执行并妥善保存）：

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

2. 执行 `docker compose up -d --build`。容器端口仅映射本机 `127.0.0.1:3001`，由 Caddy 或 Nginx 提供 HTTPS。`PUBLIC_ORIGIN` 应为最终外部 HTTPS Origin，不带末尾斜杠。
3. 用 HTTPS 域名打开网站，输入初始化令牌并创建管理员。生产环境 Cookie 要求 HTTPS，不能用公网 HTTP 直接登录。
4. 验证权限、备份恢复、实际业务数据和性能后再投入正式使用。Docker 配置尚未在本机运行验证。

数据库在 Docker 命名卷 `keran-data` 中。小团队先采用单机 SQLite；数据量和导入并发增大后考虑 PostgreSQL、后台导入任务及对象存储。本版同步导入大文件会短暂占用服务线程，适合先期低并发内部使用。

## 数据库备份

运行中的 SQLite 使用 WAL，**不要只复制主数据库文件**。使用 SQLite 备份 API 生成一致性快照：

```sh
node scripts/backup.mjs
```

默认保存到 `data/backups/`。也可指定备份目录：`node scripts/backup.mjs /safe/backup/path`。生产容器中可执行：

```sh
docker compose exec web node scripts/backup.mjs /app/data/backups
```

请将备份再复制到服务器之外并设保留策略。恢复时停止服务，将快照放回数据库位置，确认旧的 `-wal`、`-shm` 属于停机前数据库，不与恢复快照混用，然后启动并核对数据。备份包含账号哈希与业务数据，按内部敏感资料保管。
