## 证据和工具边界

- 通过用户授权账号对原站做只读观察。原站账号、密码、经营金额和人员资料不进入代码、文档或截图。
- 使用官方 npm 包 `rea-agents@6.7.0` 的 `analyze-javascript-application` 分析公开浏览器脚本中的 OwnerDashboard、CompanyWorkspace 和 login 三个文件。证据保留在被 Git 忽略的本地 `.tools/`，没有安装常驻 REA 服务。
- 导航目录使用 REA 依赖的 Babel AST 解析公开脚本文本。这部分不是 REA 语义分析覆盖范围；不能据此声称已获取私有后台源码。
- [静态目录](../../reference-inventory.md) 提供11模块、69候选条目。候选存在匹配片段、外链和待确认路由，并不等于69个已验证独立页面。JSON 保留取证时的 pending 状态；实现进度以本文件和后续验收记录为准。

- [x] 登录页：品牌布局、账号密码、显示/隐藏密码、错误反馈、首次创建管理员。记住我仅保存账号。

- [x] 经营提醒：依据当前与等长前期数据生成，查看触发指标和原始经营记录。未声称已分派负责人或处理任务。

- [x] 独立审查及修复渠道范围污染、初始化状态回归和日期错误恢复；浏览器操作验收。

本批的首页与快捷工作是可用启动入口，还不是原站完整个人/部门工作流；未实现业务入口禁用并标注待还原。原站业务API、会计口径、人员分摊和智能分析尚未接入，不能宣称整站完成或给出未经量化的相似度百分比。
